## 用户任务

在 `xuebadictApp` 生产 Flask API 中直接复用 GitHub 上与当前链路匹配的开源实现，让千问和 DeepSeek 具备官方 SDK 调用路径，同时保留无密钥模拟联调能力。

## 研究结论

- [dashscope/dashscope-sdk-python](https://github.com/dashscope/dashscope-sdk-python)：阿里云官方 DashScope Python SDK，Apache-2.0；用于千问文本生成。
- [openai/openai-python](https://github.com/openai/openai-python)：OpenAI 官方 Python 客户端，Apache-2.0；用于 DeepSeek 的 OpenAI 兼容 Chat Completions 调用。
- [QwenLM/Qwen-Agent](https://github.com/QwenLM/Qwen-Agent)：确认 DashScope OpenAI-compatible endpoint 的消息协议；本任务不引入其完整 Agent 框架。
- [chippeddog/english.now](https://github.com/chippeddog/english.now)：英语学习产品交互参考；TypeScript/Expo 与当前 Flutter/Dart 基座不兼容，本任务不复制其代码。

## 范围

- 增加 `AI_CLIENT=official_sdk` 选择官方 SDK；默认 `AI_CLIENT=http` 保持现有 HTTP provider 行为。
- 千问 provider 在官方 SDK 模式调用 `dashscope.Generation.call`。
- DeepSeek provider 在官方 SDK 模式调用 `openai.OpenAI(...).chat.completions.create`。
- SDK 导入采用懒加载，模拟模式不需要外部 SDK、不发网络请求。
- `/api/v1/ai/providers` 暴露当前 client 类型，方便联调环境识别。
- 更新依赖、来源/许可证记录、任务日志和结果收据；不读取、打印或提交密钥。

## 不在范围

- 不将 Qwen-Agent、english.now 或其他整仓库复制进生产线。
- 不改 Flutter 调用协议；不改变已有模拟输出和训练状态机。
- 不在本任务伪造真实模型成功，不做真实 API 密钥联网验证。

## 验收条件

- [x] `AI_MODE=simulation` 仍注册 qwen/deepseek，且不依赖官方 SDK。
- [x] `AI_CLIENT=official_sdk` 时两个 live provider 均绑定对应官方 SDK 实现。
- [x] 官方 SDK 异常、超时和非预期响应会返回当前 `ChatResponse` 错误格式，不静默成功。
- [x] 默认 `AI_CLIENT=http` 的现有 provider 注册和请求路径不变。

- [x] 任务、日志、结果和 registry 状态一致；外部来源、许可证和未验证边界有记录。
