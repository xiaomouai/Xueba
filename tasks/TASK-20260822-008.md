## 用户任务

先完成后端 AI 的模拟接入，让 Flutter 工作英语页面在没有外部模型密钥时，也能稳定演示千问/DeepSeek provider、知识卡生成、文字反馈和重说链路。

## 现状与约束

- 现有 `QwenProvider` 和 `DeepSeekProvider` 已负责真实 HTTP 请求；本 task 不替换真实适配器。
- 现有配置只有在 API key 和 base URL 同时存在时才注册 provider；无密钥环境无法演示。
- 模拟模式必须显式开启，不得在 `live` 模式静默伪造 AI 响应。
- 不读取、打印、提交任何 API 密钥；不调用外部 Qwen/DeepSeek 网络。

## 范围

- 增加 `AI_MODE=simulation`，并兼容 `AI_SIMULATION=true`。
- 在模拟模式注册 `qwen` 和 `deepseek` 两个 provider，保留 provider ID、优先级和前端响应格式。
- 知识请求返回符合 `ChineseToEnglishPage` `EnglishKnowledge.fromJson` 的 JSON。
- speaking 请求返回首次反馈/重说通过反馈，支持页面现有状态机。
- `/api/v1/ai/providers` 返回 provider mode，方便前端或管理端识别模拟环境。
- 补充配置文档、task 日志和结果收据。

## 验收条件

- [x] `AI_MODE=simulation` 无 API key 时仍注册 qwen、deepseek。
- [x] `provider=qwen` 和 `provider=deepseek` 都能返回成功的确定性内容，且响应 provider/model 正确。
- [x] 工作英语知识请求返回目标词、推荐说法、组织顺序、起手式、搭配、例句、语法、场景、短文、演讲和 3 个中文口语提示。
- [x] speaking 首次请求要求重说，重说请求返回场景通过提示。
- [x] `AI_MODE=live` 未改变现有真实 provider 注册和 HTTP 调用行为。
